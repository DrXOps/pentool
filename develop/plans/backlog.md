## Известный долг: нативные Windows-тесты

Job `test-windows` в `.github/workflows/ci.yml` помечен `continue-on-error: true`
и красный по причинам, не связанным с кодом продукта. Владелец решил (2026-11-25)
не чинить сейчас. Что именно падает на `windows-latest`:

| Тест | Причина |
|---|---|
| `tests/unit/tui/test_check_tui_css.py` (4 теста) | открывает `/dev/null`, на Windows такого пути нет |
| `tests/unit/utils/test_lightpanda.py` (2) | ожидает POSIX-пути: `\\usr\\local\\bin…` против `/usr/local/bin` |
| `tests/unit/utils/test_cert.py` (2) | `os.chmod`-семантика: файл остаётся `666` вместо `600` |
| `tests/unit/tui/test_autosave_mixin.py` | имя воркера `save-1-<ns>` совпадает в пределах миллисекунды |
| `tests/unit/modules/test_proxy.py` | `reuse_port` не поддерживается сокетами Windows |
| `tests/unit/tui/test_intruder_toolbar_wiring.py` (2) | таб-бар Intruder монтируется иначе |
| `tests/unit/tui/test_intruder_tabs.py` | `#template-panel-…` не появляется |

Чинится по одному тесту: `tmp_path` вместо `/dev/null`, `pathlib`/`PurePosixPath`
вместо склейки строк, `unittest.mock` вместо реального `chmod`, `run_id` из
`itertools.count()` вместо `monotonic_ns`, `skipif(sys.platform == "win32")` там,
где поведение платформы действительно разное.

## На обдумывание (не в плане)

### Батчинг обновлений таблицы истории Proxy

**Идея:** собирать входящие перехваченные запросы в буфер и применять раз в 100–200 мс
одной пачкой, вместо вставки строки на каждый запрос.

**За:** при 1000 запросов подряд каждая вставка — это изменение модели таблицы и
перерисовка; батчинг снимает нагрузку с UI-потока.

**Против / вопросы, которые надо решить до реализации:**
- история перестаёт быть «живой»: строка появляется с задержкой до 200 мс — для
  перехвата это может быть неприятно (сейчас видно сразу);
- нужен порядок сортировки и сохранение нумерации (`#`, время) при пачке;
- что делать при переключении подвкладки/фильтра посреди накопления буфера;
- FTS-поиск и `batch_update` на `fastdatatable`: проверить, есть ли выигрыш на самом
  деле (замер до/после), а не по ощущениям.

**Решение:** отложено владельцем 2026-11-24. Возвращаться только с замером: снять
профиль при 1000 запросов и сравнить «как есть» против буфера.
