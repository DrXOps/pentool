## Интеграция Recon (перенос из `plan-recon-integration.md`)

Recon сейчас — отдельный экран: надо открыть его, ввести домен и запустить. Найденное
живёт в своём отчёте и никуда не уходит. Предлагается цикл «увидел → разведал →
попало в карту → проверил сканером → AI расставил приоритеты».

1. **[x] «Отправить в Recon» из контекста — СДЕЛАНО 2026-11-23** (`cdb1b12`, PRO
   `7073dce`, указатель `28f97d5`). Пункты в `RequestContextMenuMixin` (`host only` /
   `subdomains` / `endpoints` / `real IP` / `fuzz params`), один вход
   `PentoolApp.open_recon(target, mode, run=False)`; FREE-код не импортирует PRO-символы
   (duck-typing через `prepare_recon`), меню скрыто без фичи `ai_discovery`. PRO-экран
   запускает только запрошенные стадии. Побочно исправлено: Recon держал состояние в
   `self._running` — внутреннем флаге Textual `MessagePump`. Оценка была 0.5 дня.
2. **Находки сами попадают в Target** — событие `ReconDiscovered` через EventBus,
   подписчик добавляет узлы с пометкой источника (`source="recon"`), дедуп по
   нормализованному URL, значок 🛰 и фильтр «только найденное разведкой».
3. **Найденное используют Scanner и Intruder** — цели скана из сайтмапа, «все
   Recon-эндпоинты в табы Intruder», пометка хостов разведки в истории Proxy.
4. **AI на данных Recon** — ранжирование «что проверять первым», набор проверок для
   эндпоинта (с подтверждением, без автозапуска), summary отчёта в ленте Dashboard.

Оценка: фаза 1 — 0.5 дня, фаза 2 — 1 день, фаза 3 — 1 день, фаза 4 — 0.5–1 день.

## Запуск с целью: `--smart` / `--real`

Симптом и причины — в [tech_debt.md](../tech_debt.md), P1. Смысл доработки: запуск с
целью должен давать **немедленную** обратную связь в истории Proxy, а не тишину на
3–5 секунд, и не превращать `host:port` в POST `/v2`.

1. **Нормализация цели** — `host:port` → `https://host:port/` (или http по порту),
   чтобы fetch шёл на корень, а не на технический путь.
2. **Параметр `--wait-ms`** вместо константы 3000: по умолчанию 500–1000, отдельный
   флаг для «дождаться JS».
3. **Мгновенная запись в историю**: сразу после старта добавлять строку
   «GET <target> — fetching…» (pending), заменяя её реальным запросом и статусом,
   когда fetch завершится. Пользователь видит, что запрос принят.
4. **Разделить режимы**: `--smart` — «проверить хост и показать в истории» (без
   браузера, мгновенно), `--real` — «прогнать через браузер с JS» (может быть медленно,
   с явным индикатором прогресса).
5. **Таймаут телеметрии** lightpanda (`OperationTimedout`) — не блокирует результат,
   но уменьшение `--wait-ms` убирает шум из логов.

Оценка: 1–1.5 дня (нормализация + pending-строка + флаг + тесты).

  сервис по выбору пользователя).

## Коллабораторы (F-02)

Встроенный канал (PRO, `team_collab`) + кастомный URL, который пользователь задаёт
сам. Модель: `collab_channel = {kind, url, token?, enabled, last_sync}`. В события
не попадают тела запросов без отдельного флага. Нужны: `services/collab_service.py`,
поле в Settings → Collaboration, эндпоинты `/api/collab/push|pull` в воркере.
Оценка: 2–3 дня. **Требует решения:** что синхронизируем (только находки / ещё карту).
