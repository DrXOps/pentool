# Аудит TUI — чистота кода, универсальность, поддержка

**Дата:** 2026-11-21. **Область:** `pentool/tui/` (FREE-часть) + замечания по
`pro/pentool/tui/`. **Контекст:** редизайн закрыт, дизайн в `develop`; этот аудит
— про внутреннее качество, а не внешний вид.

Методика: AST-разбор пакета, подсчёт повторов и длины функций, сверка
существующих гвардов (`tools/check_*.py`), чтение границ ответственности
`app.py` / экранов / виджетов. Замеры производительности — в
`MYPLANS/plan-release-2026-11-20.md`.

## 1. Что сделано хорошо (не трогать)

- **Ноль магических цветов**: ни одного `#rrggbb`/`rgb()` в `.tcss` — только
  токены темы. Единая точка оформления — `app.tcss`.
- **Ноль TODO/FIXME/HACK** в `pentool/tui`.
- **Гварды вместо договорённостей**: `check_tui_css` (591 селектор сверяется с
  DOM), `check_lazy_screens`, `check_english_comments`, `check_broad_except`
  (трещотка вниз), `check_silent_except`, `check_logging_policy`, `check_layers`.
- **Контракт шапки** (`header.py`) — данные вместо императива: экран описывает
  шапку `HeaderSpec`, приложение рисует. Это лучший кусок архитектуры TUI.
- **Тесты-структуры**, а не тесты-снимки: `test_on_selectors_resolve`,
  `test_handler_name_dispatch`, `test_app_mixin_surface`, `test_dialogs_unified`,
  `test_filter_bar_unified` ловят классы дефектов, а не один случай.

## 2. Находки (по убыванию важности)

### A1. Три файла-монолита (P1)

| Файл | Размер | Строк | Что внутри |
|---|---|---|---|
| `screens/intruder/screen.py` | 142 KB | ~3100 | экран + сборка таба (`_mount_tab_body` — 206 строк) + атака + экспорт |
| `app.py` | 121 KB | ~2400 | компоновка, шапка, модули, хоткеи, проект, нотификации |
| `screens/proxy/screen.py` | 114 KB | ~2400 | экран + история + перехват + WS + фильтры + инспектор |

Самая длинная функция пакета — `IntruderScreen._mount_tab_body` (**206 строк**),
затем `SettingsScreen.compose` (**204**), `IntruderScreen._mark_all_params` (181),
`PentoolApp.on_mount` (174), `action_start_attack` (129), `_seed_pending_urls` (128).

**Почему это про поддержку:** любая правка требует держать в голове весь файл;
`git blame` по «где собирается панель payload'ов» ведёт в 3000-строчный файл.

**Предложение:** разрезать по ответственности, не меняя поведения:
`intruder/screen.py` → `layout.py` (сборка подвкладки), `attack.py`
(запуск/пауза/стоп/прогресс), `results.py` (таблица, экспорт, фильтр);
`app.py` → `header_render.py` (слоты `#hdr-*`, уже изолированы методами),
`module_switch.py`, `project_actions.py`; `proxy/screen.py` → `history.py`,
`intercept.py`, `ws.py` (часть уже вынесена в `widgets/intercept.py`).

### A2. Дублирующийся метод в каждом экране (P2)

`_refresh_header_now()` продублирован в **5 экранах** (4 идентичных тела по 4
строки + 1 на 8), каждый — `getattr(self.app, "refresh_header", None)`.

**Предложение:** один метод в `AppMixin` (он уже есть у всех экранов), экраны
его не объявляют. Гвард: тест «ни один экран не объявляет `_refresh_header_now`».

### A3. Два несовместимых способа обращения к виджетам (P2)

В пакете **202** присваивания `self.query_one(...)` и только **147** обработчиков
`except NoMatches`. То есть ~55 мест падают, если виджет не смонтирован — а с
ленивыми подвкладками (Proxy) и ленивыми экранами это теперь **штатная**
ситуация. Хелпер `mixins/safe_query.py` (`safe_query_one`) существует, но
используется **0 раз** — код писался до него.

**Предложение:** перевести «обращения из обработчиков событий» на
`safe_query_one(...)` (он логирует контекст и возвращает `None`), оставив прямой
`query_one` только там, где отсутствие виджета — ошибка программиста.

### A4. Шесть экранов не описывают шапку (P2 → универсальность)

`header_spec()` есть у: dashboard, proxy, repeater, intruder, utils.
Нет у: target, settings, extensions, decoder, comparer, sequencer — их шапка
пустая (только полоса модулей). Это не баг, но разрыв единообразия: пользователь
видит одинаковый хром в пяти модулях и «голую» строку в шести.

**Предложение:** по одному заходу на экран (подвкладки — чипами, действия —
кнопками). Контракт уже готов, работы на 10–20 строк на экран.

### A5. Разнобой базовых классов (P2 → универсальность)

| Экран | База |
|---|---|
| intruder | `BaseModuleScreen` + 6 миксинов |
| repeater | `BaseModuleScreen` + 3 миксина |
| proxy, dashboard, target, settings, extensions, utils | `Widget` + миксины |
| decoder, comparer, sequencer | `ContentClipboardMixin, AppMixin, Widget` |

`BaseModuleScreen` даёт только «двойной клик по табу → переименование», но
определяет ожидания («табовые экраны наследуют его»).

**Предложение:** ввести `ModuleScreen(Widget)` = `AppMixin` + базовые «пустые»
реализации `header_spec/header_action/header_tab_selected` + `_refresh_header_now`
(из A2). Тогда `BaseModuleScreen` останется специализацией для табовых модулей.

### A6. `run_worker` вместо единого хелпера (P3)

В `proxy/screen.py` — **29** вызовов `run_worker`, в `intruder` — 11. Паттерн
повторяется: `self.run_worker(self._reload_...(filters), exclusive=…)`.
Часть групп задаётся строками (`"repeater-send"`, `"proxy-tabs"`).

**Предложение:** реестр групп-констант (`WORKER_GROUPS`) + хелпер
`_run_reload(worker)`; это ещё и убирает опечатки в именах групп (уже была
история с `intruder-attack-<tab>`).

### A7. Ленивые подвкладки — паттерн есть только у Proxy (P3)

`_LazyTabBody` + `_populate_tab` живут в `screens/proxy/screen.py`. Intruder уже
имеет похожую механику в `TabbedContentPanel`, Utils — нет (3 тела всегда).

**Предложение:** вынести `_LazyTabBody` в `widgets/lazy_pane.py` и переиспользовать
в Utils и в табах Intruder.

### A8. Журнал: остались «шумные» широкие обработчики (P3)

После чистки (`logger.debug("op", exc_info=True)` → осмысленные сообщения) в
`pro/` осталось 13 `E402` (импорты после `_CSS`) и `_sync_ai_ui` с широким
`except`. E402 безвредны, но ломают «импорты сверху» в глазах читателя.

**Предложение:** перенести `_CSS = Path(...).read_text()` ниже импортов в PRO-экранах.

## 3. Итоговая оценка

| Критерий | Оценка | Комментарий |
|---|---|---|
| Чистота кода | **хорошо** | линт и трещотки держат планку; мешает только размер трёх файлов |
| Универсальность | **средне** | контракт шапки есть, но 6 экранов вне его; три базы классов; `safe_query` не используется |
| Удобство поддержки | **средне-хорошо** | гвардов много и они полезные; длинные функции и монолиты усложняют точечные правки |
| Производительность | **хорошо** | наш код: reload 4.7 мс, шапка 0.2 мс, layout 3.2 мс на 209 виджетов |

**Порядок работ (если продолжим):** A2 (30 минут) → A3 (2–3 часа, по экранам) →
A4 (по экрану за заход) → A1 (по одному модулю за заход, начиная с Intruder) →
A6/A7 → A8.
