## Где мы сейчас

Слой вырос до 25 тысяч строк, и рос он копированием по месту, а не абстракциями:
главный критерий владельца — расширяемость — просел. При этом защита слоя хорошая:
четыре блокирующих гейта и восемь AST-гвардов живы, «молчаливых» `except` нет,
CSS-строк в Python нет, ADR-7 и ADR-10 внедрены.

Пять самых дорогих мест:

| Что | Масштаб | Чем плохо |
|---|---|---|
| Каталог модулей был записан 5 раз | 6 файлов | новый модуль = 5–7 правок; списки уже разошлись (S1 это закрыл) |
| Нет общей базы экрана | 8 экранов, 6 копий `_refresh_header_now` | каждая сквозная обязанность реализуется на месте и по-своему |
| HTTP- и WS-история Proxy — две копии одного конвейера | ~400 строк | копии уже разошлись (кэш метки, лживый докстринг) |
| Два god-объекта | `IntruderScreen` 2 915 строк, `ProxyScreen` 2 363, `PentoolApp` 2 603 | любое изменение дорого, ничего нельзя переиспользовать |
| Диалоги и настройки | 11 + 1 файл | 4 формы Escape, 2 вида кнопки, 21 копия сохранения настроек |

  неизвестным именем.
* **S5. Команды `pentool license …`** (не существуют) убраны из интерфейса и сообщений.
* **S6. Ссылка на цены** в Settings вела на 404.

## Как проверять

```bash
uv run pytest tests/unit/tui -q          # 83 файла тестов слоя
uv run pytest tests/unit -q              # весь юнит-уровень
python tools/check_layers.py             # слои
python tools/check_lazy_screens.py       # ленивое монтирование экранов
uv run python tools/check_tui_css.py     # селекторы .tcss против DOM
uv run python tools/check_silent_except.py
uv run python tools/check_broad_except.py
uv run python tools/check_logging_policy.py
```

Правило при правках: если инвариант важен («один ряд действий», «экран не лезет в
приватные поля app», «у каждого модуля есть экран»), он должен быть проверяем — тестом
или AST-гвардом. Всё, что не проверяется, уже разъехалось один раз.
