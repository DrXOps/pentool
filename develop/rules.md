# Правила ведения документации

## Что где

| Что | Где |
|---|---|
| Документация для пользователей и сайта | `docs/` |
| Планы (только несделанное), аудиты, ADR, состояние | `develop/` |
| «Что сейчас правда» | `develop/state.md` ← генерируется из `tools/facts.yml` |

## Четыре правила

1. **Сделал — удали из плана.** Не помечай `✅` в плане: вычеркни пункт и добавь одну строку
   в [DONE.md](DONE.md) — дата, что, чем проверено. План без пунктов удаляется целиком.
2. **Один вход.** Любой новый документ в `develop/` получает строку в [README.md](README.md);
   удалённый — строку теряет. Проверяется `tools/check_docs.py`.
3. **Кратко.** Аудит — находки и решения. Правила — таблицы. Состояние — факты с проверкой.
   Если документ можно сократить вдвое, его нужно сократить вдвое.
4. **История не редактируется.** Аудиты и снимки — `audits/ГГГГ-ММ-ДД-тема.md`, заморожены.
   Нужна новая ревизия — новый файл с новой датой.

## Закрытие задач

- Результат проверяется автоматически (тест, гвард, факт) → закрываю сам: строка в
  `DONE.md`, пункт из плана удалён, факт в `tools/facts.yml` если нужен.
- Нужен ручной тест (как выглядит, ощущения) → **не закрываю**: в плане остаётся пункт
  «проверить вручную» и что именно смотреть.

## Чего не делать

- Не заводить второй файл на ту же тему.
- Не писать в `docs/` про разработку: этот каталог уходит на сайт.
- Не оставлять в плане то, что уже сделано.
