Why it exists

Fewer switches, more work

Pentool does not try to replace your whole toolkit. It removes the shuffling between tools: the target, the requests, the findings and the report live in one project.

The target is one command

pentool --url https://target creates a project, adds the target and starts the proxy. Requests appear in the history right away.

Runs over SSH

A terminal, tmux, a server with no desktop. Keyboard and mouse, dark and light themes — nothing to configure on the client side.

A project is a folder

Traffic history, findings and reports sit in SQLite next to the project: come back in a month or hand it to a colleague.

Reports, not screenshots

Findings export to HTML, JSON or CSV, plus a bulk Bug Bounty report and exports for HackerOne, Bugcrowd and DefectDojo.

Scanner · PRO

What it actually checks

Active checks send requests to the target and confirm a finding; passive checks read the responses that already flow through the proxy.

  • Injection: SQLi (error-, time- and boolean-based, UNION), NoSQL, SSTI, LFI, path traversal, RCE, header and host header injection
  • Client side: XSS, DOM XSS, prototype pollution, open redirect
  • Access and data: broken auth, JWT none, OAuth, CORS, sensitive data in responses
  • Services: SSRF, XXE, GraphQL
  • Passive: missing security headers, information leaks, sensitive data, DOM XSS

Findings land in a table with severity, evidence and the request that produced them — ready to replay in Repeater. Reports export to HTML, JSON or CSV; the bulk one follows the Bug Bounty template.

The check list grows between releases. If yours is missing, a plugin can add one.

Artificial intelligence

The model runs on your machine, not in a cloud

AI in Pentool is a small local model. It runs on your CPU, is off by default and sends nothing outside your machine.

What it does

Picks checks for the target's technology, generates payloads, tries WAF bypass for XSS, re-checks findings and suggests endpoints while crawling.

Where it runs

On your machine: a model of about 350 MB is downloaded once and runs on the CPU — no graphics card needed.

What leaves

Requests, responses and findings stay in the project. Pentool has no cloud provider — there is nowhere for the traffic to go.

When to enable it

Optional, in Settings → AI. Without the model the regular checks still run and finding analysis falls back to simple heuristics.

AI is an assistant, not a replacement for checks: the final call on a finding is yours.

Automation

Scanning inside a pipeline

The same scanner runs without the interface — --headless. Works in GitHub Actions, GitLab CI and any shell.

bash
$ pentool --url https://example.com --headless \
--check xss,sqli --threads 20 --delay 0.2 \
--format html --output report.html
# exit code: 0 — success, 1 — scan failed, 2 — bad arguments

More flags: --crawl --depth, --ai, --format json.

Your own checks ship as a plugin: BasePlugin can register a screen, a CLI command, a scanner check and a passive check. Plugins live in ~/.config/pentool/plugins, the API is documented.

Installation

Two commands to the first request

The package comes from PyPI. No Docker, no JDK, no external proxy.

bash
$ uv tool install pentool
$ pentool --url https://example.com
▶ Dashboard · Proxy · Repeater · Intruder · Scanner · Target · Utils · Extensions · Recon · Settings

No uv? pip install pentool works too. Pentool creates its own certificate for HTTPS.

Use a modern terminal: Windows Terminal, iTerm2, GNOME Terminal, Kitty, Alacritty or WezTerm. On Windows, WSL2 is the smoother path.
