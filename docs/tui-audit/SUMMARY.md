## 2. Что сделано по итерациям

Итерации D0–D7 из ТЗ; часть работ осталась за границей этой ветки и
перечислена в §5.

### D0 — composition root и слои
- `PentoolApp` остаётся единственной точкой сборки (ADR-1, ADR-4).
- TUI перестал импортировать `modules`: `auto_scope._tech_detect_and_cache`
  теперь зовёт `services.tech_detector.run_fingerprint` /
  `fingerprint_from_html` / `cache_tech_profile` (F-003).
- `tools/check_layers.py` — 148 файлов, 0 нарушений.

### D1 — базовые компоненты и мёртвый код
- Удалены `widgets/start_stop_mixin.py` (90 строк) и
  `widgets/filter_connector.py` (88 строк) вместе с их тестами (F-019, F-039).
- `Toolbar(id=None)` по умолчанию — дубль `#toolbar` на шести экранах
  исчез (F-006, F-018).
- `ContentPanel`, `Toolbar`, `ToolbarButton`, `StartStopWidget`,
  `ResizeHandle` зафиксированы как базовый набор (`COMPONENTS.md`).

### D2 — иерархия сообщений и reactive
- `ContentClipboardMixin` переведён с `@on` на соглашение об именах —
  в миксине `@on` не регистрируется вовсе (ADR-3, F-001).
- `AiModeSyncMixin` — единственное место подписки на `AiModeChanged`
  для трёх экранов (ADR-12, F-002).
- `ProxyDataTable` постит `ContextMenuRequest` / `CommentIconClicked`
  вместо `hasattr`-обхода предков (ADR-10, F-041).

### D3 — блокирующие вызовы → воркеры

  отмена через `WorkerManager.cancel_group` — прежний `workers.cancel(name)`
  не существовал, `except Exception` это скрывал (ADR-11, F-045).

## 4. Самые значимые изменения

1. **`ContentClipboardMixin` на именованных хендлерах** — одна правка
   вернула копирование/вставку на шести экранах.
2. **`test_handler_name_dispatch.py`** — AST-гвард, который делает
   повторение этого класса ошибок невозможным.
3. **`AiModeSyncMixin`** — подписка и отписка в одном месте, вместо трёх
   разных реализаций с разной степенью поломки.
4. **`AutoSaveMixin._start_save_worker` + `cancel_group`** — отмена
   автосейва действительно доходит до воркера (тест на живом
   `WorkerManager`).
5. **`ProxyDataTable` постит сообщения** вместо `hasattr`-обхода предков —
   сообщение адресуется владельцу таблицы, а не «первому предку с таким
   методом».
6. **`services.tech_detector.fingerprint_from_html()`** — TUI перестал
   тянуть класс из `modules`.
7. **`Toolbar(id=None)`** — шесть экранов больше не делят один id.
8. **Переписанные тесты copy/paste** — проверяют буфер и `TextArea`,
   а не отсутствие исключения.
9. **Удалено 178 строк мёртвого кода** (`filter_connector`,
   `start_stop_mixin`) вместе с тестами к ним.
10. **`wiki/tui.md` + этот каталог** — инварианты Textual 8, на которых
    спотыкался код, теперь записаны рядом с кодом.

`action_new_tab()` выставляет `_active_tab_id` на новую вкладку сразу, а
`TabActivated` приходит позже и первым делом зовёт `_save_current_tab_state()`
— а тот читает именно это поле. К моменту вызова там уже новая вкладка, её
редактор ещё не собран, сохранение выходит no-op (его страхует `ui_ready`), и
набранный текст остаётся только в виджете. Видимая потеря возникала на
восстановлении проекта: вкладка открывалась с прежним запросом. Исправление —
сохранять текущую вкладку **до** создания новой. Гвард:
`tests/unit/tui/test_repeater_tab_state_survives.py` (три теста: правка при
открытии новой вкладки, правка при обычном переключении, закрытие вкладки —
состояние и панель снимаются, соседняя вкладка цела, последняя не закрывается).

**Добавлено 2026-11-16 (персистентность вкладок Repeater):** 🟡 47. Новая
находка **F-053**: закрытая вкладка Repeater возвращается после перезапуска.
Набор вкладок не хранится — он выводится из последних 20 строк таблицы
`repeater_entries` (группировка по `tab_name`, новейшая запись на имя), а
`action_close_tab()` чистит только `_tabs` и панель. У Intruder для этого есть
отдельная таблица с `tab_uid` и `delete_tab()`, у Repeater аналога нет, поэтому
закрытие — чисто визуальное действие. Это изменение модели хранения
(отдельная таблица вкладок либо удаление строк истории при закрытии), а не
правка в один хунк, поэтому вынесено в F-053, а не сделано молча.

**Добавлено 2026-11-16 (реестр вкладок):** ✅ 48. F-053 закрыт отдельной
таблицей `repeater_tabs`: `tab_uid` — стабильная идентичность вкладки (переживает
переименование и перезапуск), `request_text` — содержимое, `sort_order` —
порядок. Запись идёт upsert'ом по uid, закрытие вызывает `delete_tab`, а
`repeater_entries` остаётся историей отправок и закрытием не чистится — это лог,
а не реестр вкладок. Вкладка попадает в реестр сразу после сборки тела, поэтому
переживает перезапуск даже без правки.

Попутно вскрылся дефект перезагрузки проекта: `_close_all_tabs()` снимал панели
по одной, и внутренний `Tabs` успевал обновить `active` по уже исчезнувшей
панели — `ValueError: No Tab with id '--content-tab-tab-N'`. Проявлялось только
когда на экране одна вкладка (частный случай: проект переоткрыли сразу после
монтирования). Переведено на `TabbedContent.clear_panes()`.

Отдельно про тесты: экраны читают путь к базе из конфигурации машины, поэтому
unit-прогон писал в историю настоящего проекта (после прогона у пользователя
появлялись вкладки, которых он не создавал). `tests/unit/tui/conftest.py` уводит
`AppMixin._get_db_path()` в пустоту для всех TUI-тестов; тестам с настоящей
схемой путь задаётся через `tmp_path`.
