# proxy

**Изоляция прокси в отдельном процессе: демон + клиент поверх unix-сокета.**

- **Связи:** [[modules]], [[tui]], [[core]]
- **Код:** pentool/proxy/
- **Источник:** pentool/proxy/__init__.py (docstring «П.3»)
- **Обновлено:** 2026-11-05

## Назначение

Прокси живёт в **отдельном процессе**, а не внутри TUI. TUI общается с ним
только через локальный unix-сокет (команды внутрь, события наружу). Это
устраняет целый класс сбоев «прокси на демон-потоке делит память/EventBus с TUI»
(гонки мыши, `run()` вернулся, а прокси жив, протечки состояния).

## Публичный интерфейс

- `ProxyDaemon` (`daemon.py`) — процесс прокси.
- `ProxyClient` (`client.py`) — тонкий клиент для TUI.
- `ProxyServer` — сама реализация, живёт в [[modules]].

## Инварианты и подводные камни

- Всё общение — через сокет; никакого общего состояния с TUI.
- Падение демона не должно ронять UI: клиент обязан корректно обрабатывать
  разрыв соединения и переподключение.

## Связи

Инкапсулирует `ProxyServer` из [[modules]]; используется [[tui]] через
`proxy_service` / `ProxyAPI`.
